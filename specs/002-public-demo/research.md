# Research: Public demo

**Date**: 2026-10-02. Research informs planning, not implementation evidence.

## R1: Static hosting and real HTTP/SSE

**Decision**: Same-origin worker answers reserved endpoint fetches using respondWith/Response and
readable byte streams. Real fetch/HttpAgent/recorder/frame-reader path remains unchanged.
**Rationale**: Pages is static; workers handle normal POST HTTP requests and streamed responses.
Locally generated bytes remain observable through the browser fetch stack.
**Alternatives considered**: Remote examples add operated services/external dependencies; MSW adds
an unnecessary package; in-app fake transport or imported recordings fail interactive wire-path
requirements. No cache/offline shell needed.

**Sources**: [Pages overview](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages),
[SW fetch event](https://www.w3.org/TR/service-workers/#fetch-event-section),
[MDN fetch event](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/fetch_event).

**G-D03 proof required**: First-load HTTP/SSE, byte equality/malformed tail, cloning and native
stop/cancellation of both readers and producer. SW streaming does not guarantee TCP chunk
boundaries; compare complete bytes/order and progressive availability.

## R2: First visit, scope, unsupported browsers

**Decision**: Classic bundled sibling service-worker.js; scope page directory under
/agui-inspector/; updateViaCache none. Listen before registering; install skipWaiting, activate
clients.claim; verify matching controller/script/scope/version handshake within 10 seconds.
**Rationale**: A sibling worker needs no root-scope Service-Worker-Allowed header. Ready registration
alone does not prove the fresh page is controlled; claim avoids manual reload. Identity/version
prevents a stale/unrelated controller being accepted.
**Alternatives considered**: Root scope affects other sites; reload heuristics can loop/drop state;
ready-only races first POST; module worker adds compatibility requirements; fake fallback violates I.

Unavailable examples show reason/reload guidance/docs and mount the same app with absent optional config;
own-server/import remain usable. No example POST before readiness or replay on controller change.

**Sources**: [Register](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register),
[Claim algorithm](https://www.w3.org/TR/service-workers/#clients-claim),
[Using SW](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).

## R3: Existing scenarios / shared pure producer

**Decision**: One pure scenarios.ts owns extracted interactive branching/wire generation and
exposes existing pure A2UI/protocol helpers to both adapters. Protocol producer identifiers may
be parameterized with unchanged defaults.
**Rationale**: Only mixed-I/O interactive logic needs extraction; existing neutral modules need
not move. Node logs/failure controls/CORS stay Node-only.
**Alternatives considered**: Copied events diverge; core demo branches violate III; generic
server/transport factory adds unnecessary abstraction.

| Inspected existing path | Preserve/reuse |
| --- | --- |
| examples/reference-agent/interactive-scenarios.ts | Plain/interrupt/tools/slow/never finishes/state/broken and resume/tool/action branching; preparations, CORS, request order, failures, open-stream control. |
| examples/reference-agent/server.ts | CLI loopback startup JSON, health/preflight, 400 malformed JSON/422 missing IDs, plain deterministic SSE. |
| examples/reference-agent/a2ui-scenarios.ts | Already pure v0.9 operations/continuation, second/deleted surfaces, malformed/external-resource tests. |

| examples/reference-agent/recorder-fixtures.ts | Pure fragmentation/exact byte assembly/status/type/ending descriptors; no Node I/O. |
| examples/reference-agent/config-scenarios.ts | Existing preset variables, ordered preparation and quick-message syntax; remains unchanged. |

Demo wraps existing A2UI operations in supported activity events and forwards recorded action
envelopes to existing continuation. No Node I/O modules enter the worker dependency graph.

## R4: Startup CSP / visitor policy / loopback limit

**Decision**: Strict hosted-only optional allowVisitorTargets boolean in existing startup policy
chain: parseHostingConfig -> policyFor -> installPolicy -> resolveTarget. Default off. Adds https:
and http://localhost:*; numeric sources only supported/advertised with proof.
**Rationale**: Existing guard handles config/capability/preparation/run/raw paths and already omits
hosted cookies/refuses userinfo/redirects. Footer currently claims origin-only and must change.
Static HTML has script/object/base restrictions but no connect-src; intersected startup meta can
establish chosen connect scope without widening a pre-existing restriction.
**Alternatives considered**: All-http CSP + JS guard fails defense-in-depth and was rejected by
coordinator; wildcard * is worse; replacing numeric addresses with localhost changes Host/routing/
auth and is not approved.

**Escalated limit**: CSP3 host matching rejects non-domain hosts and lacks portable IPv6 literal
syntax. Do not claim http://[::1]:* works. Coordinator confirmed 2026-10-02: guarantee configured
HTTPS/localhost boundary; re-prove IPv4 in Playwright Chromium, record Firefox/Safari manually,
leave IPv6 unclaimed and recommend localhost. G-D02 is a technical limit inside the approved
opt-in, not a product re-decision. Constitution permits intended loopback set subject to browser
enforcement. Native CORS/local-network permissions still apply.

**Strict opt-in combination**: Fixed-origin entries cannot widen the opted-in HTTPS/loopback
boundary. Reject out-of-bound combinations at startup and in a constructed runtime policy;
default-off allowlists retain their old semantics.

**Sources**: [Host matching](https://w3c.github.io/webappsec-csp/#match-hosts),
[Multiple policies](https://w3c.github.io/webappsec-csp/#multiple-policies),
[connect-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/connect-src),
[worker-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/worker-src).

Keep local A2UI assets/catalogs, same-origin scripts/no eval, same-origin worker, volatile
credentials/unchanged target echoes and export rules. No inspector approval prompts; do not
promise bypass of browser permission prompts.

## R5: Shared app / isolated build

**Decision**: Reuse buildApp(outdir)/bundleOptions from scripts/build.mjs; new build-demo.mjs writes
only .build/public-demo. Bootstrap imports built shared app as external module, uses separate root
and explicit mount. Reuse the existing ordinary-root auto-mount guard; add config-file override only.
**Rationale**: Existing build supports another outdir; existing budget --dir counts complete assets.
Ordinary static/npm/Python default paths stay unchanged.
**Alternatives considered**: Worker in package public ships it to distributions; parallel app
duplicates runtime/renderer and budget; global URL rebasing changes integrations.

**URL trap**: Existing agent/preparation references resolve against origin, not document.baseURI.
Prefix only checked-in demo paths at build time, as absolute URLs (hosted mode refuses relative endpoints); config/worker sit beside page. Preserve normal
config/user URL semantics. No required root manifest dependency edit.

## R6: Pages workflow / reviewed pins

**Decision**: Main-only push/guarded manual workflow, build/deploy jobs, github-pages environment,
serialized deployment, PR validation only and no automatic settings changes.
**Rationale**: Minimum build contents-read and deploy pages-write/id-token-write; deployment needs
successful upload; checkout persist-credentials false. Only isolated demo artifact uploaded.
**Alternatives considered**: Branch publishing misses requested artifact actions; PR deployment

## R7: Natural pacing of scripted answers (FX9)

**Decision**: One pure `pacing.ts` transform over `ScenarioResponse`, applied by the worker to the agent
routes (and available to the Node adapter as an opt-in profile). It cuts streamed deltas and adds
position-hashed pauses; delivery uses an abortable sleep on the adapter's own timers.
**Rationale**: Whole replies in one millisecond looked fake and hid how a stream builds up. A transform
at the adapter keeps producers pure (R3), covers every scenario, including later ones, without edits, and
lets a unit test inject the sleep. Byte-exact fixtures stay evidence: fragments and malformed frames pass
through, and a delta with no start event is left whole.
**Alternatives considered**: Delays written into each scenario duplicate timing and put timers in pure
producers; pacing in the page or recorder would touch the wire path (principle I); `Math.random` jitter
makes runs unreproducible; a visitor-facing speed control adds surface that no requirement calls for.

## R8: A slow run that finishes, and a run that never does (FX10)

**Decision**: The `slow` quick message streams a reply of a few sentences slowly and finishes. A new
`never finishes` quick message keeps the old behavior: it streams one sentence that says it waits for
Stop, then holds the response open. The slow run gets its pace from a `pacing: 'slow'` hint on its
response, which `pace` maps to a slower profile.
**Rationale**: Visitors read a message labeled slow that then hangs as a bug. Stop and the missing
terminal finding still need a response that stays open, so that case gets its own name and says what it
does. A hint on the response keeps timers out of the producer and the worker unchanged, and a unit test
can total the schedule on an injected clock without waiting 6 to 10 seconds.
**Alternatives considered**: Sleeping inside the `slow` producer breaks R3. Making the worker look at the
message text to pick a profile puts scenario knowledge in the adapter. Keeping one scenario and relabeling
it still leaves no run that is slow and complete.

## Research closure

Coordinator confirmed direction after CSP escalation. No unresolved design question; G-D01 through
G-D05 remain evidence/authorization gates. Research does not certify numeric-IP compatibility,
native SW abort propagation, asset budget or configured Pages availability.
