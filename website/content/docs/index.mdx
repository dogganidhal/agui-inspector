When your [AG-UI](https://docs.ag-ui.com) agent stops replying or a client rejects its events, agui-inspector shows you
the request and the stream. It sends runs to your server, keeps each frame it receives in order with its timing, and
reports JSON, schema and event-sequence problems. You can compare the conversation with the recorded frames and answer
interrupts, tool calls and A2UI surfaces as a client does. You can also send a raw JSON request to test how your server
handles invalid input.

The recording uses the public demo. In the first run, one frame opens to show its bytes as received, then the request
that started the run. The second run is a slow reply, and its frames appear on the timeline and in the list as they

## Ways to run it

It works with any AG-UI server over HTTP and Server-Sent Events (SSE), whatever language the server is written in. All
modes use the same static bundle. The hosted page and the static assets work with any server. The embedded helper
exists for Python first, and helpers for other languages follow: JavaScript helpers for Express, Hono and Next.js are
planned for 1.0.0.

| Mode | How it runs | Status |
| --- | --- | --- |
| Hosted | A static page that you point at your server. The public demo is one. | Available: the [demo](./demo.mdx), or build the page from a checkout |
| Embedded | A Python helper mounts it next to your Starlette or FastAPI agent routes, on the same origin. | 0.1.0 on PyPI: [install it](./embedding.mdx#quick-start) |
| Static assets | Any other server serves the directory that the npm package's `staticAssetsPath` points to. | Available from a source checkout |

[Project status and privacy](./status.mdx) lists the planned modes and helpers.

## What it promises

- The inspector keeps every frame it receives, raw, in arrival order and with its timing. This includes frames that are
  not JSON, fail the schema or break the event sequence. It reports them and never drops, repairs or
  reorders them.
- It sends no telemetry. The page talks only to its own origin and to the targets you configure.
- A token you type stays in memory. The inspector never writes it to storage, recordings, exports or logs, and the
  recorder reads no headers. If a server repeats the token in a payload, the inspector keeps those bytes as received
  ([read this before you share a file](./recordings.mdx#read-this-before-you-share-a-file)).
- `@ag-ui/core` and `@ag-ui/client` handle the protocol, and A2UI's own renderer draws A2UI surfaces. There is no chat
  framework between the network and the views.

[PyPI](https://pypi.org/project/agui-inspector/) since 2026-10-03. The npm package is not published yet. [Project status and privacy](./status.mdx) describes what you can rely on today.
