title: Theming
description: The ten public CSS custom properties that restyle every view, and how to deliver overrides.
---

Every color, radius, spacing step and font in the inspector's views comes from ten public CSS custom properties named `--agui-*`. The views derive every other value from those ten with `color-mix()`, `oklch()` and `calc()`. Override any of them, with a stylesheet or with the `theme` field of `config.json`, and every view changes with no rebuild. They are the contract between the views and anyone who restyles them.

This documentation site uses them too: it imports the inspector's `tokens.css` and builds its colors, fonts and radius from them.

The default build requests nothing from outside its own origin. Fonts are system font stacks, and no rule in either stylesheet uses `@import`, `@font-face` or `url()`.

## Public properties

You can override a single property. The others keep their defaults.

| Property | Light default | Dark default | Controls |
| --- | --- | --- | --- |
| `--agui-accent` | `var(--agui-fg)` | follows `--agui-fg` | Primary buttons, selection, focus ring, interrupt outline, brand mark |
| `--agui-accent-contrast` | `var(--agui-bg)` | follows `--agui-bg` | Text and icons drawn on the accent |
| `--agui-tint-hue` | `75` | same | Hue of the neutral tint, in degrees of the OKLCH color space |
| `--agui-tint-chroma` | `0.006` | same | Strength of the tint. `0` gives pure grey |
| `--agui-bg` | `oklch(0.993 c×0.6 h)` | `oklch(0.175 c×1.2 h)` | Page background |
| `--agui-fg` | `oklch(0.235 c×2.2 h)` | `oklch(0.93 c×1.2 h)` | Body text, and the source of every neutral |
| `--agui-radius` | `8px` | same | Base of the radius scale |
| `--agui-density` | `1` | same | Spacing multiplier. `0.85` is the compact setting |
| `--agui-font-sans` | `ui-sans-serif, system-ui, -apple-system, "Segoe UI", sans-serif` | same | Interface text |
| `--agui-font-mono` | `ui-monospace, "SF Mono", Menlo, Consolas, monospace` | same | Frames, ids, JSON, offsets |

`c` is `--agui-tint-chroma` and `h` is `--agui-tint-hue`. The default accent is the text color, so the default inspector is monochrome and your accent is the only hue in the interface. Avoid a red, amber or green accent. Those hues mean errors, warnings and success, and a primary button in one of them looks like a status.

This stylesheet override works in light and dark mode as written:

```css
:root {
  --agui-accent: oklch(0.52 0.19 262);
  --agui-accent-contrast: oklch(0.99 0 0);
  --agui-tint-hue: 262;
  --agui-radius: 4px;
  --agui-font-sans: "Source Sans 3", system-ui, sans-serif;
}
```

## Dark mode

Dark values apply when the root element has `data-theme="dark"`. They also apply when the system prefers a dark color scheme and the root element does not have `data-theme="light"`. The theme switch in the top bar sets `data-theme`.

Only `--agui-bg` and `--agui-fg` change between the modes, plus the internal lightness of the status and event-family colors. The inspector sets these two again in both dark rules:

```css
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }
:root[data-theme="dark"] { … }
```

Those rules are more specific than a plain `:root` rule. So if your stylesheet overrides `--agui-bg` or `--agui-fg` in `:root` alone, dark mode ignores it. If you override either, set dark values too, in the same two rules with the same selectors. The other eight properties need no dark version.

## Delivering overrides

There are two ways, and you can combine them.

### In config.json

Add a `theme` field with optional `light` and `dark` maps. Every deployment mode reads it: hosted, embedded, the Python helper's `theme=` argument ([embedding](./embedding.mdx#theming-the-embedded-page)) and any server that serves the assets next to a `config.json`. It needs no stylesheet, rebuild or extra request.

```json title="config.json"
{
  "version": 0,
  "agents": [],
  "theme": {
    "light": { "--agui-accent": "#2563eb", "--agui-radius": "6px" },
    "dark": { "--agui-accent": "#93c5fd", "--agui-radius": "6px" }
  }
}
```

- The page accepts only the ten public names, with string values. Anything else, and any unsafe value (`url(`, `image-set(`, `@`, `;`, `{`, `}`, a backslash), causes a visible "Configuration" warning under the top bar. The page still starts normally. [Configuration](./configuration.mdx#theme) has the full rules.
- The page sets the map for the current mode as custom properties on the root element, through the CSS object model. This needs no request and no change to the content security policy. It follows mode changes. The top-bar switch wins over the system preference. Until you use the switch, a system preference change applies the other map.
- A property you leave out keeps its default, and a mode with no map uses that mode's defaults. So the dark map does not need to repeat the light one. A map sets only the properties it names, so the dark map can set `--agui-bg` and `--agui-fg` without matching the inspector's dark selectors.
- The page applies the map after its stylesheets, so the map wins when both set the same property.

### With a stylesheet

Load your stylesheet after the inspector's own, and set the public properties on `:root`, as in the example above. The [dark mode rule](#dark-mode) applies only to stylesheets.

Custom properties inherit through shadow roots, so an element inside one gets the same properties from its host element.

## Fonts

The inspector loads no font. To use a brand font, load it with your own `@font-face` and name it in `--agui-font-sans` or `--agui-font-mono`. The bundle may include a font file if it fits the bundle budget, but the default build includes none.

## Host page styles

The other tokens the views read are internal and derived from the ten. Do not override them. Their names are short and have no prefix. So the inspector declares them, with their dark versions, on its mount element `#root` and never on the document's `:root`. A host page that already defines `--bg`, `--fg`, `--line`, `--muted`, `--acc` or `--r` cannot change the inspector's derived values, and the inspector does not overwrite the host's. The ten public properties stay on `:root`. Their names have a prefix, an override must sit on the same element as the defaults built from it, and they are the contract.

The application shell sets its background, text color and font on `#root` instead of `body`, so the surrounding document reads no inspector token. Dialogs, popovers and toasts are DOM descendants of `#root`, even when they show in the top layer, and no view renders outside it. So they keep the inspector's styles on a host page whose styles conflict. Every primitive class name starts with `agui-`, so none collides with host CSS.

## Check your overrides

Open the inspector in light and dark mode to check your overrides. In the default themes, the conversation's frame references and offsets have a contrast of at least 4.5:1 against their background. Colors you set are not checked, so check their contrast yourself.

If a value is rejected, read the "Configuration" warning under the top bar. [Configuration](./configuration.mdx#theme) has the rules. To change the shared tokens or components, see [Architecture and UI internals](./internals.mdx#theme-tokens).
