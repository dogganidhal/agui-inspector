Every direct dependency has an exact version in a `package.json` and resolves through a committed
`package-lock.json`. Installs run no lifecycle scripts (`.npmrc` sets `ignore-scripts=true`). A dependency is added
only for a proven need, and its row says why the platform or an existing dependency could not do the job. "The
constitution" in a row means the project's
[constitution](https://github.com/dogganidhal/agui-inspector/blob/main/.specify/memory/constitution.md). The
repository uses npm workspaces and Node 24 LTS (`engines.node` is `>=24`).

## License and notices

The project is MIT, `Copyright (c) 2026 Nidhal Dogga` (`LICENSE`). `THIRD_PARTY_NOTICES.txt` lists every
non-development package in `package-lock.json` (42 at the time of writing) with its license. It says which of them
`dist/app.js` bundles and includes the full license texts, such as the Apache-2.0 text for `@a2ui/react`,
`@a2ui/web_core` and `@a2ui/markdown-it`. No listed package, these three included, ships a `NOTICE` file. For
packages whose tarball has no license file (`@bufbuild/protobuf`, `@lit-labs/ssr-dom-shim`, `@protobuf-ts/protoc`),
the file uses the text from their upstream repository and says so.

The notices come from the license files in the installed packages. Regenerate them when a dependency changes. A
Python test fails when a runtime package in the lockfile is missing from the file, or when an upstream `NOTICE` file
is missing from it. npm and `uv_build` cannot pack files from outside the package, so both package directories
have byte-identical copies of `LICENSE` and `THIRD_PARTY_NOTICES.txt`, and a test compares them.

## Known upstream findings

These come from the pinned baseline. They are recorded here, not worked around by changing the baseline.

### DOMPurify override

`@a2ui/react` 0.12.0 depends on `@a2ui/markdown-it` 0.2.0, which pins DOMPurify 3.4.11. That version is affected by
[GHSA-c2j3-45gr-mqc4](https://github.com/advisories/GHSA-c2j3-45gr-mqc4) and
[GHSA-55q2-fjhq-7xh7](https://github.com/advisories/GHSA-55q2-fjhq-7xh7). The root `package.json` sets
`"overrides": { "dompurify": "3.4.16" }`, and the committed lockfile resolves exactly 3.4.16. Check it with
`npm ls dompurify --all`. The override changes neither the required renderer nor the direct dependency list.

The production bundle does not include DOMPurify or `@a2ui/markdown-it`. The conversation's Markdown view uses
`markdown-it` directly and builds React elements, so it needs no sanitizer (see the `markdown-it` row above). The
override protects the installed tree and any future use of the renderer's Markdown path.
The v0.8 renderer imports `markdown-it` too, but the inspector draws v0.8 text itself, so that renderer never turns Markdown into HTML.
Remove it when A2UI ships a fixed pin, and review the lockfile in the same change. The lockfile was updated with
`npm update dompurify --ignore-scripts`, so no lifecycle script ran.

### CRLF and CR event streams

`@ag-ui/client` 1.0.1 splits events with `split(/\n\n/)`, so its parser fails on a stream whose lines end in CRLF or
in a lone carriage return (CR) ([issue #49](https://github.com/dogganidhal/agui-inspector/issues/49)). The client
loses the run. The next request then has neither the assistant's reply nor the updated state, although the recording
and the conversation look correct.

On 2026-10-03, the last version in `npm view @ag-ui/client versions` was 1.0.1 (published 2026-09-29), with no later
version or dist-tag. The 1.0.1 tarball still split on line feeds (LF) only. The upstream fix,
[ag-ui-protocol/ag-ui#2939](https://github.com/ag-ui-protocol/ag-ui/pull/2939), was opened on 2026-10-02. At the time
of writing it is not reviewed, merged or released, so the pin stays at 1.0.1.

Until a release contains the fix, the runtime gives the client a copy of the response with LF line endings
(`packages/inspector/src/core/runtime/line-endings.ts`). The recorder clones the response first, so recorded
envelopes, arrival order and findings keep the server's bytes. The recorder's own frame reader still splits on all
three delimiters. Nothing else about the client's input changes. This is the only exception to "the
client's stream is untouched", written into principle I of the
[constitution](https://github.com/dogganidhal/agui-inspector/blob/main/.specify/memory/constitution.md) and described
in [Architecture and UI internals](./internals.mdx#the-recorder).

LF, CRLF, CR and streams that mix them give the same messages, state and outcomes, including interrupt and client
tool continuations. No other line ending is supported. A frame that is not valid JSON still ends the client's run as a
finding, and capture continues.

Two tests check this:

- `packages/inspector/tests/runtime/line-endings.test.ts` checks the next request body (state and message roles)
  after a run over each line ending.
- `packages/inspector/tests/foundation/compatibility.test.ts` pins the client's LF-only framing.

When the compatibility test fails after an update, remove the copy: delete `line-endings.ts` and its call in
`runtime/index.ts`, remove the exception from principle I, from the
[MVP specification](https://github.com/dogganidhal/agui-inspector/blob/main/specs/001-inspector-mvp/spec.md) and from
the internals page, and delete this section.

### Other findings

- `@ag-ui/a2ui-middleware` imports Node's `crypto` at module scope. `scripts/build.mjs` resolves that import to a
  small browser replacement: `randomUUID` comes from Web Crypto, and `createHash` throws.
- `clarinet`, which the middleware depends on, calls `require("stream")` inside a try/catch. The browser bundle keeps
  that guarded call.
