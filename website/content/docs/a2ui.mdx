An A2UI surface is a form or other interface that your agent describes and the inspector draws inside an activity card. You fill it in and press its buttons as a user would. Each action starts a run that sends it to your agent, so you can check the surface and your agent's answer. The inspector draws A2UI v0.8 and v0.9 surfaces and finds the version of each one itself.

The left pane shows the activity card, with its Rendered and JSON switch at the top. The frames list on the right shows the snapshot and each delta that built the board, with arrival times. To try it, pick the A2UI showcase agent in the [demo](./demo.mdx) and choose Deploy the release.

## Use a surface

- A surface appears when your agent sends an `ACTIVITY_SNAPSHOT` of type `a2ui-surface`, and changes with each `ACTIVITY_DELTA`.
- Switch the card to JSON to see the operations as received. Switching back redraws the surface and loses typed text.
- Fill in the fields and press a button to start a run that sends the action to your agent (see [Actions](#actions)).
- Two independent [client profile](./configuration.mdx#client-profile) settings apply, each a switch in Settings. Render A2UI surfaces (`renderA2ui`) turns surface drawing on or off. Inject render_a2ui tool (`injectA2uiTool`) adds the official `render_a2ui` tool declaration to the run input.

## What is drawn

An `ACTIVITY_SNAPSHOT` of type `a2ui-surface` carries `{ "a2ui_operations": [...] }`, a list of A2UI messages. v0.9 messages are `createSurface`, `updateComponents`, `updateDataModel` and `deleteSurface`. v0.8 messages are `beginRendering`, `surfaceUpdate`, `dataModelUpdate` and `deleteSurface`. A list can hold both. `@a2ui/web_core` builds the surfaces, and `@a2ui/react/v0_9` or `@a2ui/react/v0_8` draws them. Both are [pinned](./dependencies.mdx) and bundled, so surfaces render offline.

| Situation | What you see |
| --- | --- |
| Rendering on, valid operations | One block per surface |
| Rendering off | The operations as JSON, with a note that rendering is off |
| Another activity type | JSON in the activity card, outside this view |
| No `a2ui_operations`, `status` of `building`, `retrying` or `failed` | The status (see [generation lifecycle](#generation-lifecycle)) |
| No `a2ui_operations`, any other case | "No A2UI operations yet." |
| An entry that is neither v0.8 nor v0.9 | An error naming its position, with the entry as received. The others still apply (see [versions](#versions)) |
| An operation the renderer cannot apply | An error naming its position, with the entry as received. The others still apply |
| `a2ui_operations` is not a list | One error showing the value received |
| A component type not in the catalog | An error in its place naming the type, with its definition under "As received". The rest still draws |

## Versions

The inspector reads the version from each entry of `a2ui_operations`, so there is no setting for it. One list can hold surfaces of both versions.

| Entry | Version |
| --- | --- |
| An object with `"version": "v0.9"` | v0.9 |
| An object with no `version` that holds `beginRendering`, `surfaceUpdate`, `dataModelUpdate` or `deleteSurface` | v0.8 |
| Anything else | Refused |

`deleteSurface` exists in both versions, so the `version` key decides which one it is.

A refused entry gets an error with its position, and the entry itself is under "As received". Every other entry still applies. The three errors are:

| Entry | Error |
| --- | --- |
| Not an object | `This operation is not an object.` |
| An object with no version and no v0.8 message name | `This operation has no version and no v0.8 message name. A2UI v0.9 operations declare "version": "v0.9".` |
| A `version` other than `v0.9` | `This operation declares version v0.8. A2UI v0.9 operations declare "v0.9", and v0.8 messages have no version.` |

The v0.8 protocol has no `version` field, so a message that declares `v0.8` is refused. A v0.8 message can also fail the v0.8 check: two message kinds in one message, an unknown key or a missing required field. Its error names the problem and the position.

A surface has the version of the messages that build it. A v0.8 surface and a v0.9 surface can share an id. They are two surfaces, and a message changes only the surface of its own version. Surfaces appear in the order the list first names them, whatever their version.

## Actions

When a user activates a control, the surface creates an action with exactly five fields:

```json
{
  "name": "send_note",
  "surfaceId": "form",
  "sourceComponentId": "send",
  "context": { "note": "edited by hand", "count": 1 },
  "timestamp": "2026-10-02T14:47:13.359Z"
}
```

The renderer resolves the bindings in `context`, copies it at the click and sets `timestamp`. The inspector puts the object in `forwardedProps.a2uiAction.userAction` and starts a normal [run](./runs.mdx). It never sends the action as a tool reply.

A v0.8 button names its action as `{ "name": "send_note", "context": [{ "key": "note", "value": { "path": "/note" } }] }`. At the click the renderer turns the `context` list into an object, with the data that each path holds. The action reaches your agent in the same five fields. A path that points at an object gives that object as JSON.

## How operations are applied

On each change, the inspector passes the activity's operation list to a session. An identical list changes nothing. A list that only grew at the end applies the new entries and keeps typed text. Any other change, such as an `ACTIVITY_DELTA` that rewrites an earlier operation, rebuilds the surfaces and loses typed values. This is the same for both versions.

The session gives the renderer copies, so the received list never changes. Typing into a bound field changes only the surface's data model. The JSON view, the frames, the exported session and the projection still show what the agent sent.

## Generation lifecycle

`@ag-ui/a2ui-middleware` 0.0.11 sends an `a2ui-surface` snapshot before there is anything to draw, then replaces it under the same message id. Its `status` sits next to `a2ui_operations`, never inside it, and shows while there are no operations:

| `status` | Fields read | What you see |
| --- | --- | --- |
| `building` | `progressTokens` | A pulsing "Building" tag, "The surface is being generated." and the token estimate if any. Announced as a status |
| `retrying` | `attempt`, `maxAttempts`, `errors` | A "Retrying" warning with "Attempt 2 of 3". Announced as a status |
| `failed` | `error`, `attempts`, `maxAttempts` | A "Failed" error with the middleware's message and "3 of 3 attempts used". Announced as an alert |

The inspector lists `errors` (a list of `{ path, message }`) under "Validation errors (n)". For `failed`, it adds the `errors` of each `attempts` entry. The server's `debugExposure` sets that list to `hidden`, `collapsed` (default) or `verbose` (open). `attempts` can also be a number. Operations, when present, take priority over the status. An unknown status shows "No A2UI operations yet."

## Nothing leaves the page

A surface cannot make the inspector request, open or load anything:

- `Image`, `Video` and `AudioPlayer` become a note with the address as plain text. The inspector creates no `img`, `video` or `audio` element.
- `openUrl` only adds a visible "Blocked openUrl ..." line.
- No Markdown renderer is configured, so link and image syntax stay as typed.
- The Material Symbols font behind `Icon` names never loads.
- Catalogs are never fetched.
- The v0.8 renderer tries to inject a stylesheet into the document head when it starts. The page's content security policy forbids inline styles, so the inspector prevents that and styles v0.8 surfaces itself. The policy is the same with and without v0.8 surfaces.

## Catalogs and aliases

The inspector bundles two catalogs and never fetches one. A surface names its catalog by id: `createSurface.catalogId` in v0.9, and the optional `beginRendering.catalogId` in v0.8.

| Catalog id | Catalog | Where it comes from |
| --- | --- | --- |
| `https://a2ui.org/specification/v0_9/catalogs/basic/catalog.json` | v0.9 basic | Declared by the renderer package |
| `https://a2ui.org/specification/v0_9/basic_catalog.json` | v0.9 basic | The default of `@ag-ui/a2ui-middleware` 0.0.11 when the agent sets none. This is the one built-in alias |
| `https://a2ui.org/specification/v0_8/standard_catalog_definition.json` | v0.8 standard | The default that the v0.8 protocol names. A v0.8 surface that names no catalog uses it |

Any other id gives "Catalog not found: <id>" with the entry as received, and the surface is not drawn. The v0.8 processor does not look at `catalogId`, so the inspector checks it. Matching is exact: a trailing slash, another scheme or another case makes a different id. The inspector never rewrites `createSurface` or `beginRendering`, so the activity JSON and the recording show the id the agent sent.

### Aliases

If your agent names a catalog by an id that used to be valid, map that id to a bundled catalog with `catalogAliases` in `config.json`:

```json
{
  "version": 0,
  "agents": [{ "id": "support", "url": "/agents/support/stream" }],
  "catalogAliases": {
    "https://catalogs.example.com/old/basic.json": "https://a2ui.org/specification/v0_9/catalogs/basic/catalog.json",
    "https://catalogs.example.com/old/standard.json": "https://a2ui.org/specification/v0_8/standard_catalog_definition.json"
  }
}
```

- The key is the id the agent sends. The value must be the id of a bundled catalog, from the table above.
- An alias serves the surfaces of its target's version. A v0.8 surface that names an alias of the v0.9 catalog gets "Catalog not found".
- An alias cannot point at another alias, and it cannot redefine an id in the table, the built-in one included.
- A bad entry gives a warning under the top bar, and the page ignores that entry. The agents and the other aliases still work. [Configuration](./configuration.mdx#catalog-aliases) lists each warning.
- For the Python helper, pass `catalog_aliases` to `mount_inspector` ([embedding](./embedding.mdx#catalog-aliases)).

Loading a catalog from an address is not supported.

## Components

These are the components of the v0.9 basic catalog. [A2UI v0.8 surfaces](#a2ui-v08-surfaces) covers v0.8.

All 18 basic-catalog components are bundled. The inspector draws eight itself (`Row`, `Divider`, `Icon`, `Button`, `TextField`, `ChoicePicker`, `Tabs`, `Modal`), because the renderer's markup has no labels or its styles never load. They keep the official schemas and bindings, so basic-catalog surfaces work unchanged.

| Component | Behavior |
| --- | --- |
| `Text` | All variants. `h1` to `h5` are real headings, `caption` is small and muted, `body` is plain text |
| `Image`, `Video`, `AudioPlayer` | A note with the address as text (see [nothing leaves the page](#nothing-leaves-the-page)) |
| `Icon` | A named icon shows its name in a small tag, announced as an image with that name. An `svgPath` icon draws normally |
| `Row` | Wraps instead of overflowing. `justify`, `align` and `weight` work |
| `Column`, `List` | The renderer's own. `List` takes a fixed list or a template, `children: { "componentId": "row", "path": "/items" }`. In the template, a path without a leading slash resolves inside the item |
| `Card` | Bordered and padded, no shadow, no outer margin |
| `Divider` | Horizontal or vertical. A vertical one takes its row's height |
| `Tabs` | WAI-ARIA tabs (`tablist`, `tab`, `tabpanel`). Only the selected tab is in the tab order. Left, Right, Home and End move to a tab and select it |
| `Modal` | Opens a native dialog over an inert page. Escape, Close or a backdrop click closes it, and focus returns to the trigger |
| `Button` | `default`, `primary`, and `borderless` (an underlined accent link). Disabled while a check fails |
| `TextField` | Label above. `shortText`, `longText`, `number`, `obscured`. A failing check's message shows under it as its description |
| `CheckBox` | The renderer's own, with an error line when a check fails |
| `ChoicePicker` | A group named by its label. `mutuallyExclusive` gives radio buttons, `multipleSelection` checkboxes, and `displayStyle: "chips"` toggle buttons with `aria-pressed`. `filterable` adds a filter field |
| `Slider` | The renderer's own: label, range input, current value |
| `DateTimeInput` | The renderer's own native date, time or date-time input |

When you write a surface:

- A `number` `TextField` stores text. If the data model held `2` and the user types 3, it holds `"3"`, and a bound action context sends `"3"`.
- The pinned renderer ignores `validationRegexp` on `TextField`. Use a `regex` check.
- A `Button` used as a `Modal` trigger still runs its own action. Give it a `functionCall` action so the modal opens locally.
- `accessibility.label` and `accessibility.description` become `aria-label` and `aria-description` only on the eight components the inspector draws. An input with a visible label takes its name from it. Otherwise `accessibility.label` applies.

## Functions and checks

This section is about v0.9. v0.8 has no functions and no checks.

A surface can call basic-catalog functions anywhere a value is dynamic: `{ "call": "formatDate", "args": { ... } }`. The pinned renderer does not need the `"returnType": "string"` from the official samples.

| Function | Arguments | Example result |
| --- | --- | --- |
| `formatString` | `value`: text with `${/path}` and `${fn(name: arg)}` parts | `Hello Ada` |
| `formatNumber` | `value`, `decimals`, `grouping` | `1,234.50`, or `1235` with `grouping: false` |
| `formatCurrency` | `value`, `currency`, `decimals`, `grouping` | `$1,234.50` |
| `formatDate` | `value` (ISO text), `format` (Unicode TR35 pattern) | `Saturday, October 3, 2026` for `EEEE, MMMM d, yyyy` |
| `pluralize` | `value`, `zero`, `one`, `two`, `few`, `many`, `other` | `No seats`, `One seat`, `Some seats` |

The check functions are:

- `required` (`value`), false for an empty string or a missing path.
- `email` (`value`).
- `length` and `numeric` (`value`, `min`, `max`).
- `regex` (`value`, `pattern`).
- `and` and `or` (`values`, at least two).
- `not` (`value`).

`openUrl` (`url`) is blocked.

`formatDate` uses UTC, so every time zone shows the same text. The `pluralize` arguments are plain strings, so `${/n}` inside `one` or `other` is not replaced. To add the count, use `formatString` around the call (`"${/n} ${pluralize(value: ${/n}, one: 'seat', other: 'seats')}"`) or as the argument (`"other": { "call": "formatString", "args": { "value": "${/n} seats" } }`).

### The CheckRule shape

`Button`, `TextField`, `CheckBox`, `ChoicePicker`, `Slider` and `DateTimeInput` accept `checks`, a list of `CheckRule` objects with exactly two required keys:

```json
"checks": [
  {
    "condition": { "call": "and", "args": { "values": [
      { "path": "/signup/terms" },
      { "call": "email", "args": { "value": { "path": "/signup/email" } } }
    ] } },
    "message": "Accept the terms and enter a valid email address"
  }
]
```

`condition` is a boolean, a binding such as `{ "path": "/signup/terms" }`, or a function call. The check passes when it is true, and `message` shows when it fails. The renderer rejects any other shape: a bare call, a call with `message` beside it, no `message`, or an extra key. Its "Validation failed for component ... checks.0 ..." appears as an operation error, and the component is not created.

Checks re-run when the data they read changes, so a button enables itself when the form becomes valid. `ChoicePicker`, `Slider` and `DateTimeInput` show no message.

### Where a failing message appears

A `TextField` shows its first failing message under itself. A `Button` shows its first failing message that no `TextField` on the surface already shows, under itself and as its accessible description. If the fields already show them all, the button stays disabled and adds no line. Fixing a field removes its message, and the button's next message, if any, takes its place.

The renderer's `CheckBox` draws its own message, and the button cannot see it. A button that repeats a `CheckBox` message shows it twice. Give the button a form-level message ("Accept the terms and fix the fields above").

## A2UI v0.8 surfaces

A v0.8 surface is built from three kinds of message. `surfaceUpdate` defines components, `dataModelUpdate` sets data as `key` and typed value entries, and `beginRendering` names the root component. The surface appears once `beginRendering` has arrived. Until then the inspector keeps its components and data, draws nothing and reports nothing. In v0.8, every component that a `surfaceUpdate` mentions must be defined in that same message.

The v0.8 renderer draws the 18 components of the v0.8 standard catalog: `Text`, `Image`, `Icon`, `Video`, `AudioPlayer`, `Row`, `Column`, `List`, `Card`, `Tabs`, `Divider`, `Modal`, `Button`, `CheckBox`, `TextField`, `DateTimeInput`, `MultipleChoice` and `Slider`. They follow the inspector's theme in light and dark mode. Every control has a role and an accessible name, and works with the keyboard. The rules in [nothing leaves the page](#nothing-leaves-the-page) apply to v0.8 too. The inspector draws eight of the components itself and keeps the renderer's own for the rest:

| Component | Behavior |
| --- | --- |
| `Text` | Plain text. A `usageHint` of `h1` to `h5` gives a heading, `caption` gives small muted text, and anything else gives a paragraph. The renderer's own `Text` turns Markdown into links and images, so the inspector does not use it, and link and image syntax stays as typed |
| `Image`, `Video`, `AudioPlayer` | A note with the address as text |
| `Icon` | The icon name in a small tag, announced as an image with that name |
| `Button` | `primary` gives the primary look. A press sends the button's action |
| `Tabs`, `Modal` | The same tabs and dialog as v0.9 (see [components](#components)) |
| `TextField`, `CheckBox`, `Slider`, `DateTimeInput`, `MultipleChoice` | The renderer's own, styled by the theme. `obscured` shows the text as typed. `MultipleChoice` is one `select`, so `maxAllowedSelections` has no effect |
| `Row`, `Column`, `List`, `Card`, `Divider` | The renderer's own, styled by the theme |

When you write a v0.8 surface:

- The renderer reads a string property that equals a component id as a reference to that component. A `Text` with `"usageHint": "h1"` next to a component whose id is `h1` is a circular dependency. Use ids such as `heading-one`.
- A `Button` used as a `Modal` entry point still sends its own action. v0.8 has no action that only opens a modal.
- A message that the renderer cannot build, such as a circular reference or a component without a required property, is reported at its position. The renderer rebuilds the whole tree after every message, so a surface that holds such a component repeats the error for each later message.
- `beginRendering.styles` can carry `primaryColor` (a `#rrggbb` value) and `font` (a name). They apply to that surface only. The primary color is used for its primary buttons, checkboxes, sliders and selected tab.
- v0.8 has no functions, checks or `openUrl`, so [functions and checks](#functions-and-checks) does not apply to it.

## Theme and size

Surfaces follow the inspector's theme in light and dark mode, so overriding the [public `--agui-*` properties](./theming.mdx#public-properties) restyles them without a rebuild.

Both renderers are in the main bundle. Adding the v0.8 renderer made the production bundle about 215 KB larger minified and about 70 KB larger gzipped. The limits are 2,000,000 and 600,000 bytes, and `npm run check:bundle:renderer` reports how much room is left. Loading a renderer on first use is not planned.
