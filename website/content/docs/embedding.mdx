---
title: Embed in your server
description: Serve the inspector from your own Starlette, FastAPI, Express, Hono or Next.js server with one helper call.
---

A helper mounts the inspector in your own server, on the same origin as your agent routes, so your own authentication applies. There is one for Python (Starlette and FastAPI) and one each for Express, Hono and Next.js. This page covers the Python helper first, starting at [Quick start](#quick-start), and the JavaScript helpers from [JavaScript servers](#javascript-servers). A server in any other language can use the [hosted page](./hosted.mdx) or [serve the static assets](#serving-the-assets-from-another-server).

The Python package `agui-inspector` (MIT) contains the prebuilt inspector files and one helper, `mount_inspector`, that serves them from your Starlette or FastAPI application. The host needs no Node toolchain, and the helper downloads nothing at startup. Version 0.1.0 is on [PyPI](https://pypi.org/project/agui-inspector/).

A helper adds a separate page to your server. That page sends its own requests to your agent URLs, so it records the runs it starts. It does not attach to the agent that your own frontend runs, and it does not see that agent's requests. Watching your application's `AbstractAgent` would need an in-app mode. The inspector has none, and the [roadmap](https://github.com/dogganidhal/agui-inspector/blob/main/ROADMAP.md#decisions) does not plan one.

## Quick start

This section and the ones up to [JavaScript servers](#javascript-servers) are about the Python helper.

<Steps>
<Step>

Install the package from PyPI with the `embedded` extra, which adds Starlette. Use pip in a virtual environment, or uv in a uv project:

```sh tab="pip" tab-group="python-installer"
pip install "agui-inspector[embedded]"
```

```sh tab="uv" tab-group="python-installer"
uv add "agui-inspector[embedded]"
```

</Step>
<Step>

Mount the inspector behind a setting that is off in production. Add this after you create your application. Replace `app` with your application object and `settings.debug` with your development-only setting.

```python
from agui_inspector import Agent, mount_inspector

mount_inspector(
    app,
    agents=[Agent(id="support", url="/agents/support/stream")],
    enabled=settings.debug,
)
```

</Step>
<Step>

Start the application and open `/agui-inspector`, for example `http://127.0.0.1:8000/agui-inspector`. The page lists the `support` agent and calls its URL directly.

</Step>
<Step>

Type `Hello` in the message box and send it. Your agent's reply appears in the conversation. The Inspection tab shows the request as one exchange, with every frame the agent streamed back.

</Step>
</Steps>

FastAPI uses the same call because it is a Starlette application. The package itself depends on no framework, so a host that never enables the inspector installs nothing extra.

## Arguments

| Argument | Meaning |
| --- | --- |
| `agents` | The agents the page lists. `Agent` needs `id` and `url`. `name`, `capabilities` and `preset` are optional and mean the same as in the [configuration file](./configuration.mdx#configuration-file). Ids must be unique. |
| `enabled` | Default `False`. A disabled call returns before it imports Starlette, registers a route or logs anything. |
| `path` | The page's path, default `/agui-inspector`. It must start with `/` and cannot be `/` alone. A trailing `/` is ignored. |
| `theme` | Optional `{"light": {...}, "dark": {...}}`. Each map is optional and maps the ten public `--agui-*` names to CSS values, for example `{"light": {"--agui-accent": "#2563eb"}}`. The helper writes it into `config.json` as given. |
| `brand` | Optional `Brand(name=..., logo=..., logo_dark=...)`. Every field is optional. The helper writes the set fields into `config.json` as given, with `logo_dark` written as `logoDark`. See [Branding the embedded page](#branding-the-embedded-page). |
| `catalog_aliases` | Optional `{"<former id>": "<bundled catalog id>"}`. The helper writes it into `config.json` as `catalogAliases`, as given. See [Catalog aliases](#catalog-aliases). |
| `plugins` | Optional list of plugin module addresses on the page's origin, such as `["/static/plugins/sign.js"]`. The helper writes it into `config.json` as given and serves no module. See [Plugins in the embedded page](#plugins-in-the-embedded-page). |

## Debug guard

<Callout type="warn">
The inspector shows request bodies, raw frames and your agent list to anyone who can reach the route. Tie `enabled` to something that is off in production, such as `settings.debug`.
</Callout>

When enabled, the helper logs one warning through the `agui_inspector` logger, for example `agui-inspector is enabled and mounted at /agui-inspector; disable it outside development`. If that warning appears in a production log, the guard is wrong.

## Theming the embedded page

The helper does not check `theme`. The page checks it when it loads `config.json`, applies the map for the current light or dark mode, and shows a "Configuration" warning for each name or value it rejects. A rejected entry never stops the page or the agents from loading. A misspelled property name gives a warning and no visible change. The rules are in [configuration](./configuration.mdx#theme) and the properties in [theming](./theming.mdx#public-properties).

`theme` changes nothing else: same routes, same content security policy header, no extra request. A host that serves the assets itself puts the same `theme` field in its own `config.json`.

## Branding the embedded page

`brand` shows your product's name and logo in the top bar, instead of the agui-inspector mark and name:

```python
from agui_inspector import Agent, Brand, mount_inspector

mount_inspector(
    app,
    agents=[Agent(id="support", url="/agents/support/stream")],
    enabled=True,
    brand=Brand(name="Acme Console", logo="/static/acme.svg", logo_dark="/static/acme-dark.svg"),
)
```

Leave out `name` when your logo already holds your product name. The logo then shows alone, with no text beside it.

The helper does not check the values and serves no logo file. Serve the logo from one of your own routes, such as a static files mount, and write its path. A logo must be a path or a URL on the page's own origin, or a `data:` image. To inline one, build the URI yourself:

```python
import base64
logo = "data:image/svg+xml;base64," + base64.b64encode(open("acme.svg", "rb").read()).decode()
```

The page checks the brand when it loads `config.json`. It shows a "Configuration" warning for each field it rejects, and a rejected field never stops the page or the agents from loading. The rules, the warnings and the dark logo are in [configuration](./configuration.mdx#brand).

`brand` changes nothing else: same routes, same content security policy header, no extra request. A host that serves the assets itself puts the same `brand` field in its own `config.json`.

## Catalog aliases

`catalog_aliases` maps an A2UI catalog id that your agent still uses to a catalog that the inspector bundles:

```python
mount_inspector(
    app,
    agents=[Agent(id="support", url="/agents/support/stream")],
    enabled=True,
    catalog_aliases={
        "https://catalogs.example.com/old/basic.json": "https://a2ui.org/specification/v0_9/catalogs/basic/catalog.json",
    },
)
```

The helper does not check it. The page checks it when it loads `config.json` and shows a "Configuration" warning for each entry it rejects. A rejected entry never stops the page or the agents from loading. The rules are in [configuration](./configuration.mdx#catalog-aliases).

`catalog_aliases` changes nothing else: same routes, same content security policy header, no extra request. A host that serves the assets itself puts the same `catalogAliases` field in its own `config.json`.

## Plugins in the embedded page

`plugins` lists plugin modules for the page to load: a run hook, header providers or renderers. [Plugins](./plugins.mdx) describes the API.

```python
from fastapi.staticfiles import StaticFiles

app.mount("/static", StaticFiles(directory="static"), name="static")
mount_inspector(
    app,
    agents=[Agent(id="support", url="/agents/support/stream")],
    enabled=True,
    plugins=["/static/plugins/sign.js"],
)
```

The helper does not check the list and does not serve a module. Serve each file from a route of your own, the way you serve a logo, with a JavaScript content type. `StaticFiles` does that for a `.js` file. An address must be on the page's own origin. The page checks the list when it loads `config.json` and shows a "Configuration" warning for each entry it rejects. A rejected entry never stops the page or the agents from loading. The rules are in [configuration](./configuration.mdx#plugins).

`plugins` changes nothing else: same routes, same content security policy header, no extra request. With no `plugins`, `config.json` is the same text as before. A host that serves the assets itself puts the same `plugins` field in its own `config.json`.

## Routes

With the default path the helper adds:

| Route | Response |
| --- | --- |
| `GET /agui-inspector` | A 307 redirect to `/agui-inspector/` that keeps the query string, so the page's relative script URL resolves. The `Location` includes the ASGI (Asynchronous Server Gateway Interface) `root_path`, which holds the prefix of every outer mount. Under `outer.mount("/api", app)` it is `/api/agui-inspector/`. |
| `GET /agui-inspector/` | The inspector page. |
| `GET /agui-inspector/config.json` | The version-0 configuration built from `agents`, `theme`, `brand`, `catalog_aliases` and `plugins`: `{"version": 0, "agents": [...], "theme": {...}, "brand": {...}, "catalogAliases": {...}, "plugins": [...]}`. Fields left as `None` are left out, and so are `theme`, `brand`, `catalogAliases` and `plugins` when you pass none. The page reads it from its own directory, so a custom `path` works the same way. |
| `GET /agui-inspector/<file>` | A packaged asset, including nested ones. Anything else is a 404. |

The helper rejects other methods. It adds no session endpoints, no storage and no proxy for the agent. The page calls your agent URL directly, and a captured session never reaches the server.

Every response carries `Content-Security-Policy: script-src 'self'; object-src 'none'; base-uri 'none'`, the same policy as the page's own `<meta>` element. Scripts load only from the page's origin, and `eval` is blocked. The helper reads assets through `importlib.resources`, rejects `..` segments and backslashes, and serves only files under the packaged `static` directory.

## Authentication

The helper adds no authentication. Whatever guards the rest of your application also guards the inspector. The page calls relative agent URLs on the same origin, so the browser sends the credentials it already has for your site. `Agent` has no field for credentials, so the configuration never contains any.

These guards cover the page, `config.json`, the assets and the slash redirect:

- Middleware on the application you pass to `mount_inspector`, or on any application that mounts it.
- A reverse proxy or gateway in front of the inspector path.
- On FastAPI, the application-level dependencies of the application you pass, as in `FastAPI(dependencies=[Depends(require_login)])`. The helper registers API routes on a FastAPI application, so those dependencies run for all four routes. The routes do not appear in the OpenAPI schema.

<Callout type="warn">
One setup is not covered: a dependency on an application that mounts yours. FastAPI does not run the dependencies of an outer application for a mounted sub-application. With `outer = FastAPI(dependencies=[...])` and `outer.mount("/api", app)`, the inspector in `app` is served and that dependency never runs. Put the dependency on `app` itself, or guard with middleware on `outer` or with the proxy. A plain Starlette application has no dependency system, so it needs middleware or the proxy.
</Callout>

The guard must accept what a browser sends when it opens a page. A plain page load sends cookies and saved HTTP Basic credentials, but it cannot send a custom header. So a guard that accepts only `Authorization: Bearer <token>` blocks the inspector page itself. Typing a token into the page cannot help, because the page never loads. Guard the inspector paths with a session cookie, HTTP Basic or a proxy that adds the credential. Your agent routes behind that guard can still require a bearer token: the page's Authentication control sends one header with each agent request. Keep the header name `Authorization` and type the complete value, `Bearer <token>`, in the Token field. See [the token](./runs.mdx#the-token).

[`examples/fastapi/app.py`](https://github.com/dogganidhal/agui-inspector/blob/main/examples/fastapi/app.py) is a host with no model. Middleware checks HTTP Basic authentication on every route. It reads `EXAMPLE_USER` and `EXAMPLE_PASSWORD` from the environment and mounts the inspector only when `EXAMPLE_DEBUG=1`. It streams one scripted run from `POST /agents/demo/stream`. From the repository root, build the package, then run the example. With pip, a virtual environment holds the package and the example's FastAPI and uvicorn, which the package's `test` dependency group lists (`--group` needs pip 25.1 or newer). With uv, `uv run` uses the locked versions:

```sh tab="pip" tab-group="python-installer"
npm run package:python
python3 -m venv .venv
source .venv/bin/activate
pip install "packages/python/dist/agui_inspector-0.1.0-py3-none-any.whl[embedded]" \
  --group packages/python/pyproject.toml:test
EXAMPLE_USER=dev EXAMPLE_PASSWORD=choose-a-password EXAMPLE_DEBUG=1 \
  python examples/fastapi/app.py --port 8000
```

```sh tab="uv" tab-group="python-installer"
npm run package:python
EXAMPLE_USER=dev EXAMPLE_PASSWORD=choose-a-password EXAMPLE_DEBUG=1 \
  uv run --project packages/python --locked --extra embedded --group test \
  python examples/fastapi/app.py --port 8000
```

Open `http://127.0.0.1:8000/agui-inspector/` and sign in with that user and password when the browser asks. The page lists Demo agent. Send any message, and the agent answers `Hello from the FastAPI example.` If port 8000 is taken, pass another `--port` and change the URL.

## JavaScript servers

The npm package `agui-inspector` (MIT) has one helper each for Express, Hono and Next.js. They do what `mount_inspector` does for Python: the same arguments, the same routes, the same warning and the same content security policy. The page comes from your own origin, so your own authentication applies.

<Callout type="warn">
The JavaScript helpers are new in `agui-inspector` 0.2.0. Version 0.1.0 on npm does not have them. Until 0.2.0 is released, build the package from a checkout and install the tarball: see [Trying the JavaScript helpers from a checkout](#trying-the-javascript-helpers-from-a-checkout).
</Callout>

### Install and requirements

```sh
npm install agui-inspector
```

- The helpers need Node.js 22.12 or newer. They read the page's files from disk, so they need the Node.js runtime. An edge runtime has no file system and cannot serve the page.
- The package installs no web framework. Each helper uses the Express, Hono or Next.js that your project already has. They are tested with Express 5.2, Hono 4.13 and Next.js 15.5 and 16.3. The Express helper needs only `app.use(path, handler)` from your application, and the Hono helper needs only `app.all(path, handler)`.
- The helpers are ES modules with type definitions. In a CommonJS file, load one with `require('agui-inspector/express')` on Node.js 22.12 or newer, or with `await import()`. TypeScript finds the types with `moduleResolution` set to `node16`, `nodenext` or `bundler`, which read the package's `exports`, and with the older `node` setting, through `typesVersions`.

### Mount the inspector

```ts tab="Express" tab-group="js-framework"
import express from 'express';
import { mountInspector } from 'agui-inspector/express';

const app = express();
app.use(requireLogin); // your own guard, if you have one, goes first

mountInspector(app, {
  agents: [{ id: 'support', url: '/agents/support/stream' }],
  enabled: process.env.NODE_ENV !== 'production',
});
```

```ts tab="Hono" tab-group="js-framework"
import { Hono } from 'hono';
import { mountInspector } from 'agui-inspector/hono';

const app = new Hono();
app.use('*', requireLogin); // your own guard, if you have one, goes first

mountInspector(app, {
  agents: [{ id: 'support', url: '/agents/support/stream' }],
  enabled: process.env.NODE_ENV !== 'production',
});
```

```ts tab="Next.js" tab-group="js-framework"
// app/agui-inspector/[[...path]]/route.ts
import { inspectorRoute } from 'agui-inspector/next';

export const { GET, HEAD } = inspectorRoute({
  agents: [{ id: 'support', url: '/api/agents/support' }],
  enabled: process.env.NODE_ENV !== 'production',
});
```

Start the server and open `/agui-inspector`. The page lists the `support` agent and calls its URL on the same origin.

Express: `mountInspector` takes an application or a `Router`. On a `Router` that you mount at `/api`, the page is at `/api/agui-inspector`.

Hono: run the application on Node.js, for example with `@hono/node-server`. Under `new Hono().basePath('/api')` or `app.route('/api', sub)`, the page is at `/api/agui-inspector`.

Next.js: Next.js has no application object, so the helper returns the `GET` and `HEAD` handlers of a route file. The folder of the file sets the path. To serve the page at `/tools/inspect`, put the file at `app/tools/inspect/[[...path]]/route.ts`. Keep the segment name `path`, in double brackets, because the helper reads `params.path`. You do not change `next.config`: the page works with the default trailing slash setting and with a `basePath`. Next.js answers the methods the file does not export.

### JavaScript arguments

| Argument | Meaning |
| --- | --- |
| `agents` | The agents the page lists. Each needs `id` and `url`. `name`, `capabilities` (an object or a URL string) and `preset` are optional and mean the same as in the [configuration file](./configuration.mdx#configuration-file). Ids must be unique. |
| `enabled` | Default `false`. Only the boolean `true` mounts. A string such as `'false'` does not, so an environment variable has to become a boolean first. A disabled call checks nothing, reads no file, adds no route and logs nothing. In Next.js the route file stays, and the route answers 404 with no inspector content. |
| `path` | Express and Hono only. The page's path, default `/agui-inspector`. It must start with `/` and cannot be `/` alone. A trailing `/` is ignored. Next.js has no `path`, because the folder of the route file sets it. |
| `theme` | Optional `{ light: {...}, dark: {...} }`. Each map is optional and maps the ten public `--agui-*` names to CSS values. The helper writes it into `config.json` as given. The page checks it, as described in [Theming the embedded page](#theming-the-embedded-page). |
| `brand` | Optional `{ name, logo, logoDark }`. Every field is optional. The helper writes the set fields into `config.json` as given and serves no logo file. See [Branding the embedded page](#branding-the-embedded-page). |
| `plugins` | Optional array of plugin module addresses on the page's origin, such as `['/static/plugins/sign.js']`. The helper writes it into `config.json` as given and serves no module: serve each file from a route of your own, with a JavaScript content type. See [Plugins in the embedded page](#plugins-in-the-embedded-page). |

A call with a bad argument stops startup and names the problem, for example `every agent needs a unique nonempty id and a url`. Nothing is mounted then. The checks run only when `enabled` is `true`.

### JavaScript debug guard

The inspector shows request bodies, raw frames and your agent list to anyone who can reach the route. Tie `enabled` to something that is off in production.

When enabled, the helper logs one warning with `console.warn`, for example `agui-inspector is enabled and mounted at /agui-inspector; disable it outside development`. Express and Hono log it when you call `mountInspector`. The warning names the path as you passed it, without an outer `Router` or `basePath` prefix.

Next.js logs it once, when the route serves its first request, and names the route's path as Next.js reports it, without a `basePath`. Next.js loads a route file on its first request, and only a request tells the helper where the route lives. A Next.js development server can log it more than once, because it loads the route file again after a change.

### JavaScript routes

With the default path the helpers add:

| Route | Response |
| --- | --- |
| `GET /agui-inspector` | A 307 redirect to `agui-inspector/index.html` that keeps the query string. The `Location` is relative, so it holds under any outer prefix, such as `/api`. |
| `GET /agui-inspector/index.html` | The inspector page. |
| `GET /agui-inspector/` | The inspector page, where your framework passes the slash form through. |
| `GET /agui-inspector/config.json` | The version 0 configuration built from `agents`, `theme`, `brand` and `plugins`: `{"version": 0, "agents": [...], "theme": {...}, "brand": {...}, "plugins": [...]}`. Fields you leave out are left out, and so are `theme`, `brand` and `plugins` when you pass none. |
| `GET /agui-inspector/<file>` | A packaged file, including nested ones. Anything else under the path is a 404. |

The page's scripts, styles and `config.json` are relative to its own address, so it must load from a URL inside the mount. The helpers redirect to `index.html`, not to the slash form, because Next.js redirects `/agui-inspector/` back to `/agui-inspector` by default and a redirect to the slash form would loop.

Express and Hono answer other methods with 405 and `Allow: GET, HEAD`. `HEAD` gets the headers of `GET` and no body. The helpers add no session endpoints, no cookie, no storage and no proxy for the agent. The page calls your agent URL directly.

Every response carries `Content-Security-Policy: script-src 'self'; object-src 'none'; base-uri 'none'`, the same policy as the page's own `<meta>` element, and the 307, 404 and 405 responses do too. The helpers serve only files from the package's `dist` directory. They answer `..`, encoded `..`, backslashes and null characters in a path with 404.

### JavaScript authentication

The helpers add no authentication. Whatever guards the rest of your application also guards the inspector, because the page and its files come from your routes. The page calls relative agent URLs on the same origin, so the browser sends the credentials it already has for your site.

Where the guard goes depends on the framework:

- Express: register the guard with `app.use` before you call `mountInspector`. A guard registered after it never runs for the inspector routes, because the inspector answers first.
- Hono: register the middleware before you call `mountInspector`, for example `app.use('*', guard)`. A middleware registered after it does not run for those routes.
- Next.js: guard with the Next.js middleware (`middleware.ts`, named `proxy.ts` from Next.js 16), with a matcher that covers the path, or check the request inside the route file. A reverse proxy in front of the path works for all three.

The guard must accept what a browser sends when it opens a page, as the [Python section](#authentication) explains: cookies and saved HTTP Basic credentials, but no custom header. Your agent routes behind that guard can still require a bearer token, which you type in the page's Token field. See [the token](./runs.mdx#the-token).

### Trying the JavaScript helpers from a checkout

Until 0.2.0 is released, build the package yourself. You need git and Node.js 24 or newer:

```sh
git clone https://github.com/dogganidhal/agui-inspector.git
cd agui-inspector
npm ci --ignore-scripts
npm run build
npm pack --workspace packages/inspector
```

`npm run build` writes the page to `packages/inspector/dist` and the helpers to `packages/inspector/lib`. `npm pack` writes `agui-inspector-<version>.tgz` in the current directory. In your project, install that file with `npm install /path/to/agui-inspector-<version>.tgz`.

## Serving the assets from another server

Any static file server can host the same inspector. The npm package exports `staticAssetsPath` from [`static-path.js`](https://github.com/dogganidhal/agui-inspector/blob/main/packages/inspector/src/static-path.js). Serve the directory it points at, put a `config.json` next to its `index.html`, and open the page. For Express, Hono and Next.js, use the [JavaScript helpers](#javascript-servers) instead. Install the package with `npm install agui-inspector`. The package also has a command, `agui-inspector`, that serves the page and relays to your server: see [Run it locally with the CLI](./cli.mdx). See also [Host the static page](./hosted.mdx).

## Working from a source checkout

Use a checkout to run the example, to try changes that are on `main` but not released yet, or to work on the package. You need git, Node 24 or newer with npm, and [uv](https://docs.astral.sh/uv/): `npm run package:python` builds the wheel with `uv build`. Once the wheel is built, you can install and run it with pip or uv.

```sh
git clone https://github.com/dogganidhal/agui-inspector.git
cd agui-inspector
npm ci --ignore-scripts
npm run package:python
```

The static files are not committed. A fresh checkout has no `src/agui_inspector/static` directory, and `mount_inspector(enabled=True)` raises an error that names `npm run package:python`. That command builds the assets, copies them into the package, writes `static.sha256` and runs `uv build`. It leaves a wheel and a source distribution in `packages/python/dist`. [Releases](./releases.mdx) describes what it checks.

To see the page working, start the example from [Authentication](#authentication). To use the built wheel in your own project instead of the PyPI release, install the file. Its name contains the version:

```sh tab="pip" tab-group="python-installer"
pip install "/path/to/agui-inspector/packages/python/dist/agui_inspector-0.1.0-py3-none-any.whl[embedded]"
```

```sh tab="uv" tab-group="python-installer"
uv add "agui-inspector[embedded] @ /path/to/agui-inspector/packages/python/dist/agui_inspector-0.1.0-py3-none-any.whl"
```
 For the package's test commands, see [Architecture and UI internals](./internals.mdx#python-package-tests).
